# config.json 与无数据卷部署

日期：2026-11-09

## 做了什么

1. **配置改由 `config.json` 承载**：新增 `JsonConfigSource`（`backend/csx/infra/settings.py`），读取 `/config/config.json`。优先级：环境变量 > `.env` > `config.json` > 默认值。文件缺失或坏掉就跳过，不影响启动。
2. **镜像不再写死数据目录**：删掉 `ENV CSX_DATA_DIR=/data`、`ENV CSX_WEB_DIST=/app/web/dist`，删掉 `VOLUME ["/data"]`。
3. **compose 去掉数据卷**：只挂两个相对目录 —— `./config:/config`（配置 + 数据库）、`./strm:/strm`；环境变量只剩 `TZ` 和 `CSX_CONFIG_FILE`。相对路径按 compose 文件所在目录解析（实测落到 `/opt/1panel/apps/csx-standalone/`），换目录部署不用改文件。
4. **数据迁移**：原命名卷里的 `csx.db` 平移进 `/config`，登录后核对任务、订阅、渠道配置均完整。

## 为什么

对齐 MoviePilot 的部署习惯：一个 `/config` 目录装下全部状态，备份/迁移就是拷目录；不再依赖 Docker 命名卷（不好定位、不好备份、换机要 `docker volume` 操作）。

排查中发现两个真问题：Dockerfile 里写死的 `CSX_DATA_DIR` 会盖掉 config.json（env 优先级更高），`VOLUME` 声明会让人以为 compose 删了卷就没事、实际 Docker 又造一个匿名卷。两个都已从镜像里去掉。

## 当前状态

- 线上镜像 `sha-ed7ad12`，容器无 volume、只有两个 bind mount，`/health` ok
- 配置：`/opt/1panel/apps/csx-standalone/config/config.json`（不入库）
- 数据库：`/opt/1panel/apps/csx-standalone/config/csx.db`
- 旧镜像与废弃卷已清理

## 教训

- **优先级要实测**：配置文件写对了不代表生效，环境变量可能在上游（Dockerfile ENV）already 覆盖。改动后必须 `docker inspect` 看实际 Env 和 Mounts。
- **VOLUME 声明是隐形的**：compose 没写 volume，Dockerfile 有 VOLUME 就会造匿名卷，`docker ps` 看不出来，`docker inspect` 才有。
- 1Panel 的 `files/save` 不会建父目录，`files/upload` 会 —— 写新路径优先 upload。
