# 重命名规则（MoviePilot 模板方案）完成总结

> 2026-11-09 · 提交 `c053f7c` · 镜像 `sha-c053f7c` · 线上已验证

## 做了什么

把写死的命名格式换成 MoviePilot 同款 **Jinja2 模板 + 变量**，用户可以自己改电影/剧集两条模板。

| 层 | 文件 | 内容 |
| --- | --- | --- |
| 领域 | `backend/csx/domain/naming.py` | 两条 MP 默认模板、`clean_segment`（按段清洗）、`normalize_relative_path`（拒绝 `..`/空段/无目录/超长） |
| 应用 | `backend/csx/application/naming.py` | `SandboxedEnvironment(ChainableUndefined)` 渲染、上下文装配（15 个变量）、模板选择、失败抛 `NamingError` |
| 应用 | `backend/csx/application/organize.py` | `organize_file(..., template=...)`：渲染失败自动回退旧格式并记 warning |
| 应用 | `backend/csx/application/organize_scan.py` | 预览与执行同源，逐文件渲染并收集 warning |
| 应用 | `backend/csx/application/transfer.py` | 转存落盘时按媒体类型选模板，注入 `episode_title` |
| 基础设施 | `backend/csx/infra/naming_config.py` | 读 `naming.*` 配置，缺省回落 MP 默认；`episode_meta` 查单集标题与总集数 |
| 接口 | `backend/csx/api/routes/naming.py` | `GET /naming`、`PUT /naming`（保存前用样例上下文校验）、`POST /naming/preview` |
| 前端 | `web/src/pages/SettingsPage.vue` | 「重命名规则」卡片：双模板、变量胶囊插光标、实时路径预览、恢复默认、错误红字 |

## 关键决策

1. **模板语义照搬 MP**：`/` 分目录、`{{fileExt}}` 自带点号、未定义变量渲染为空、`{% if %}` 控制可选段。
2. **比 MP 多四道闸**：沙箱渲染、按段清洗非法字符、路径安全校验（`..`/绝对/空段/长度）、渲染失败回退旧格式而不是让任务失败。
3. **变量先给真的**：15 个第一版可用的变量；`en_title`/`actors`/`releaseGroup` 等未接入的一律不提供，避免假值。
4. **默认即 MP 默认**：安装后无需配置就是 MP 的命名风格；旧格式只作为运行期回退。

## 踩到的坑

- **变量里带 `/` 会破坏目录结构**：先渲染再清洗是错的，必须**装配上下文时就把片名/单集标题清干净**（`clean_segment`），否则 `A/B` 会多出一级目录。
- **MP 剧集默认模板没有 `videoFormat`**（只有电影模板有），一开始按印象写错，读源码后修正。
- `render_relative_path` 里 `normalize_relative_path` 抛的是 `ValueError`，必须包成 `NamingError`，否则 `organize_file` 的兜底 catch 不到。
- 编辑 `scheduler.py` 时字符串替换把两行 import 粘在一起，直接语法错误——`pytest` 立刻暴露。
