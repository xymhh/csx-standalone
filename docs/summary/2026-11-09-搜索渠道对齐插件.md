# 搜索渠道对齐插件：更名 + 全部字段控件补齐（2026-11-09）

> 状态：已上线并通过真机验证。
> 提交 `cacb83a`，镜像 `ghcr.io/xymhh/csx-standalone:sha-cacb83a`，线上容器已切换。

## 1. 起因

用户要求：「搜源站点改成搜索渠道，然后对照插件，一一修改完善」。

核查发现：15 个渠道的**配置定义**（`search/*/definition.py`）与插件逐字一致（差异仅 `app.log` → `csx.infra.log` 导入），真正的差距在**前端渲染**：设置页只认 `text / number / password / switch` 四种类型，插件自描述里的 7 类控件（24 个字段）在 CSX 上退化成了纯输入框或直接不可用：

| 字段类型 | 字段数 | 插件行为 | 改前 CSX |
| --- | --- | --- | --- |
| `select` | 4 | 下拉单选 / 多选带搜索 | 渲染成文本框 |
| `combobox` | 2 | 标签输入（回车成 chip） | 渲染成文本框 |
| `test-source` | 14 | 内联「测试搜索」按钮 | 渲染成文本框 |
| `account` | 6 | 账户卡片（昵称/积分/等级/刷新） | 渲染成文本框 |
| `hdhive-oauth` | 1 | 授权面板（发起 + 回调校验） | 渲染成文本框 |
| `priority-order` | 2 | 可升降序的字幕组优先级列表 | 渲染成文本框 |
| `online-documents` | 1 | 多行「文档 URL + 资源类型多选」 | 渲染成文本框 |

另有两处系统性缺失：
- `show` 条件显隐被忽略 → HDHive WebAPI/OpenAPI 两套字段同时出现，PanSou 认证字段常显。
- `cols` 栅格被忽略 → 全部挤在 2 列里。

## 2. 改动

### 前端

- 导航与文案：`搜源站点 (15)` → `搜索渠道 (15)`；副标题「…搜源站点与播放参数」→「…搜索渠道与播放参数」。
- 新增 `web/src/components/config/SearchSourceField.vue`：按 `field.type` 分派 12 种控件（switch / select 单多选 / combobox / priority-order / online-documents / account / hdhive-oauth / test-source / number（min·max·step·suffix）/ password（显隐）/ textarea / text）。
- 设置页改为 12 栅格（`cols` 映射到 `sm:col-span-*`），按 `show` 表达式（`config.KEY`、`config.KEY === 'value'`）显隐；动态选项字段（PanSou 频道/插件）带「刷新」入口。

### 后端

- `csx/adapters/search/registry.py`
  - `account_info()`：构造渠道 client 调 `get_account_info()`，10s 超时 + 180s 进程内缓存，统一归一成 `{connected,name,points,level,...}`。
  - `dynamic_options()`：调用定义的 `get_dynamic_options`，12s 超时。
  - `hdhive_oauth_start()/hdhive_oauth_exchange()`：服务端 `state`（10 分钟 TTL）+ PKCE 授权 URL + 回调 URL 解析 + Token 交换，校验 client_id/redirect_uri/response_mode 三元一致。
- `csx/api/routes/sources.py` 新增：
  - `GET /settings/sources/meta`（账户只用缓存 + PanSou 动态选项）
  - `POST /settings/sources/account/{source_id}`（强制刷新）
  - `POST /settings/sources/options/{scope}/{key}`
  - `POST /settings/sources/hdhive/oauth/start`、`/hdhive/oauth/exchange`
- `_vendor_config()` 现在会先铺定义默认值再叠加已保存值，未保存时探测也有可用默认地址。

### 测试

`tests/test_api_sources.py` 新增 5 项（meta 结构、账户刷新 404/成功、选项 404/502、OAuth start 参数校验、OAuth exchange 未知 state 拒绝）。全量 311 项通过，ruff check/format 干净，vue-tsc + build 通过。

## 5. 追加：真实连通测试（2026-11-09 第二轮）

用户反馈「只有 pansou 能配置好，其它的都不能联通」。线上逐个跑 `/settings/sources/test/{id}` 定位到三类原因：

1. **泛型探针只认 `health/ping/get_account_info`**：Mikan / AnimeGarden / SeedHub / 海盗湾 / 片库 / UIndex / 在线文档 / 频道监控 都直接报「该搜索源未提供主动连通性探针」。
2. **Dian115、HDHaven 定义里没有 `create_client`**，即便填了账号也永远报「请先填写连接信息」。
3. **HDHive、UIndex 被 Cloudflare 拦截**（`Just a moment...` 403 / 浏览器验证），服务器出口 IP 直连不可用。

### 改法

- 新增 `backend/csx/adapters/search/probes.py`，为 12 个渠道各写最小真实请求：
  - 账号类：Dian115、HDHaven 直接构造 client 登录并取账户；聚影 / 蜗牛 / 盘链 走 `create_client` + `get_account_info`，未填账号时给出「请先填写 X 的账号与密码」。
  - 公开站点：Mikan、AnimeGarden、SeedHub、海盗湾、片库、UIndex 各打一次搜索并回报结果条数；在线文档读第一个文档并回报解析条数。
  - 频道监控：明确提示「不提供连通测试」。
- 探针预算从 10s 提到 30s（Dian115 登录实测 6–8s）。
- 新增全局 `search_proxy`：`GET/POST /settings/sources/global`（`http/https/socks5h` 格式校验），所有探针与 client 构造透传代理；设置页「搜索渠道」顶部加「搜索代理」卡片。
- UIndex 的 CloakBrowser/Cloudflare 失败改写为可操作提示（配代理或换渠道）。
