# 1Panel 路径拓扑与正确发布方式（法兰克福）

> 日期：2026-11-07
> 起因：把 csx-standalone 从 `/opt/csx-standalone` 挪到「MoviePilot 同级」，结果撞出一堆路径怪事
> 结论：**项目真实位置 = MoviePilot 旁边**，但**构建必须用 `docker build -`（stdin 传 context）**，因为 compose 的 build context 路径在 docker 守护进程里解析不到

## 一、这台机器有两套路径视图

| | 我在容器里 `-v /:/host` 看到的 | docker 守护进程（compose/build）看到的 |
|---|---|---|
| 应用目录 | `/opt/.1panel_clash/files/b249cde255f8453fa0d2ff46f7e76f65/` | `/opt/1panel/apps/`（**现已不存在**） |
| 实际内容 | moviepilot、csx-standalone、115-station、pansub、openlist…（30 个目录，是真数据） | — |

- 1Panel 面板的「应用安装」目录 `/opt/1panel/apps` 只是**别名**，真实数据在 `.1panel_clash/files/<hash>/` 下（hash 是 1Panel 的隔离目录）。
- 关键坑：**`/opt/1panel/apps` 这个路径现在在守护进程里也不存在了**（`ls` 报 No such file）。所以：
  - 任何 `build.context: /opt/1panel/apps/xxx` 的 compose 会退化成 `docker pull` 然后失败（`pull access denied`）；
  - 建软链 `/opt/1panel/apps → .1panel_clash/files/<hash>` **没用**：compose 仍报 `path not found`（软链目标在守护进程的 ns 里解析不到）。
  - 结论：**compose 的 build context 只能用 `/opt/<普通目录>`**。

## 二、正确做法：context 走 stdin，代码放哪都行

```bash
# 在一个挂了 /var/run/docker.sock + /:/host 的 docker:27-cli 容器里：
cd /host/.1panel_clash/files/b249cde255f8453fa0d2ff46f7e76f65/csx-standalone
tar c . | docker build -t csx-standalone:p3 -
```

- `docker build -` 把 context 当 tar 流送进守护进程，**不依赖守护进程能否看到该路径** → 代码可以老实待在 MoviePilot 旁边。
- 之后 compose 只写 `image: csx-standalone:p3`（**不要写 build 段**），`compose/operate up` 直接起。

## 四、其他踩到的坑（同一天）

1. **compose 文件不会因「删记录+重建」而更新**：`compose/operate delete` → `POST /containers/compose`（from:edit）只写 DB，磁盘上的 yaml 不变。要改 yaml 就 `files/upload` 直接覆盖那个文件。
2. **compose 里写 shell 变量必须用 `$$`**：`$D`、`$TS` 会被 compose 插值成空串，导致 `mv`/`rm` 打到根目录（我因此把 `/opt/csx-standalone` 挪进了容器层，后来重传恢复）。要么用 `$$`，要么干脆写死字面路径。
3. **一次性 compose 容器常报 `Network xxx_default Creating` 失败**，但容器其实已经跑完（exit 0/1），别被 500 误导——去 `/host/tmp/*.txt` 看结果。
4. **一次性容器别依赖 `docker compose logs`**（这版 1Panel 没有日志接口），把结果写 `/host/tmp/xxx.txt`，再用 `files/content` 读。
5. **`files/del` 才是删除接口**，`files/delete`、`files/remove` 都 404。

## 五、遗留风险（需用户决策）

MoviePilot 容器的 bind 源仍是 `/opt/1panel/apps/moviepilot`，而该路径在守护进程里已不存在。
**MP 现在跑着没事（bind 在启动时已解析），但一旦重启就会挂空目录**（配置丢失风险）。

可选修法（都要动生产，先问）：
- A. 把 `moviepilot` 目录从 clash 隔离目录搬到一个普通路径（如 `/opt/moviepilot`），改 MP 的 compose 后重启一次；
- B. 保留现状，重启 MP 前先确认面板能正常解析该路径。
