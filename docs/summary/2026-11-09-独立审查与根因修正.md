## 2. 真正的根因（已实测确认）

```python
c = create_platform_ttl_cache("probe", maxsize=10, ttl=60)
c["k"] = [{"id": "1"}]
c["k"]   # → {'__csx__': 'list', 'items': [...]}   不是 list
```

链条：
1. `_PlatformTTLCache.__setitem__` 编码一次得到 `payload`；
2. 调 `super().__setitem__(key, payload)` → `TTLCache.__setitem__` 内部 `self.set(key, payload)`；
3. 动态分派回 `_PlatformTTLCache.set`，**再编码一次**；
4. 读取只解码一层 → 拿到 wrapper dict → 遍历得到 `'__csx__'` / `'items'` 两个字符串 → 被 `isinstance(item, dict)` 过滤 → 表现为「空列表」。

受影响且用 `cache[key] = value` 写入的调用点（审查列出）：
`vendor/utils/magnet.py:171`、`vendor/search/woniu/resource.py:138,164`、
`vendor/search/pianku/client.py:186,237,291,395`、`vendor/search/uindex/client.py:145`、
`vendor/search/animegarden/service.py:85,94`、`vendor/search/piratebay/client.py:153`、
`vendor/search/hdhive/web/action.py:291`、`vendor/drive/p115/files.py:109`。

## 5. 教训（写给未来的自己）

1. **「第一次成功、第二次失败」= 缓存嫌疑，先验缓存，不要猜外部接口。**
   一行复现（`cache[k]=v; type(cache[k])`）能省 5 轮部署，约 40 分钟。
2. **`except Exception` + `return None/False` + 上层当成功** 是本项目最系统性的隐患，
   本次 5 个 bug 里有 2 个是它掩盖的。修 bug 前先 grep 这个模式。
3. **不要把绕开根因的补丁说成「根因修复」。** 换一个缓存实现只是把病灶挪走。
4. **验证要看反例**：`10.mkv` 通过不等于 `10` 通过；只看 happy path 会漏掉一半。
