## 三、必须重写的三处（新项目的真正成本）

1. **订阅状态机**：现在 `handlers/subscription/completion.py:20` 继承 MP 的 `SubscribeChain`，订阅的增删改查直写 MP 表（`subscribe_oper` 26 处）。新项目要自建订阅模型 + 缺集计算 + 洗版决策。
2. **整理链**：现在 `handlers/sync/naming.py:10-11` 用 MP 的 `TransHandler` + `FileManagerModule` 做命名与目录归类。新项目要自研「媒体文件 → 目标路径」的完整规则（模板引擎、季集对齐、多版本判重）。
3. **片名识别**：现在 `app.core.metainfo`（16 个文件引用）负责从文件名解析片名/季/集/画质。新项目要么自研解析器，要么直接接 TMDB 搜索 + 自建正则层。

## 四、许可证约束（必须先定）

现有仓库 `LICENSE` 是 **GPLv3**（继承自上游 odomu/MoviePilot-Plugins）。含义：

- 把 `drive/` `search/` 等代码搬到新项目 → **新项目必须也是 GPLv3**。
- 想闭源或换 MIT/Apache → 这 43,000 行不能直接搬，只能重写（成本翻倍）。
- 调用 MP 的 HTTP API 不传染；import MP 的 Python 模块属于链接，有传染风险。

**这是立项第一决策，直接决定「61% 可直接继承」是否成立。**

## 六、技术栈决策（2026-11-07 用户定）

**前端：React + shadcn/ui + Tailwind CSS**（取代 Vue3 + Vuetify）

选型理由：shadcn/ui 的组件是**源码复制进仓库**（不是 npm 黑盒），可以直接改样式，正好解决现在「Vuetify 组件改不动、只能写 !important 覆盖」的问题。

### 6.1 对前端资产的影响（实测）

| 部分 | 行数 | 处理 |
|---|---:|---|
| 32 个 `.vue` 的 `<script>` 逻辑 | 8,559 | 迁成 TS + React hooks（约 70% 语义保留） |
| `src/composables/` | 2,563 | 迁成 hooks（`useMediaData` / `usePageData` 等） |
| `src/config/fields.js` 配置字段定义 | 2,366 | 直接迁（数据驱动，无框架耦合） |
| `src/utils/` | 281 | 直接迁 |
| `.vue` 模板 | ~7,400 | **重写**成 JSX |
| `.vue` 的 `<style>` | 9,565 | **全废**，改 Tailwind（现 37% 是手写 CSS 补丁） |

组件映射：现有 **54 种 Vuetify 组件**，约 22 个 shadcn/ui 组件可覆盖（Card / Dialog / Button / Badge / Tabs / Table / Input / Select / Sheet / Toast / Tooltip / Progress…）。

### 6.2 配套选型

| 关注点 | 选型 | 理由 |
|---|---|---|
| 构建 | Vite + TypeScript | 产物纯静态，交给 FastAPI 托管 |
| 路由 | TanStack Router | 类型安全、文件路由 |
| 数据层 | TanStack Query | 替代 composables 里手写的轮询与缓存 |
| 表格 | TanStack Table | `HistoryTable.vue`（2,055 行）可砍一半 |
| 图表 | Recharts | 签到 / 统计 / 进度曲线 |
| 图标 | lucide-react | shadcn 默认 |
| 主题 | Tailwind v4 + CSS 变量 | 现有 `tokens.css` 的 7 个状态色直接变主题变量 |

### 6.3 工时修正

前端原估 3–5 人日（改路由 + 鉴权）→ **12–16 人日**（重写约 1.7 万行视图层 + 搭设计体系）。

**总量修正：从 27–41 人日 → 约 36–50 人日。**
