## 1. 职责划分

| 层 | 文件 | 职责 | 依赖 |
|---|---|---|---|
| infra | `csx/infra/tg_client.py` | Telethon 连接、`fetch_recent(channel, min_id, limit)`、FloodWait 重试、错误分类、断线重连 | telethon |
| infra | `csx/infra/tg_scan_state.py` | 游标读写（`Setting` 表 key `tg.scan_state`，JSON） | 标准库 + sqlalchemy |
| application | `csx/application/tg_sync.py` | 读设置 → 逐频道拉取 → 逐条调 `ingest_telegram_message` → 汇总结果 | infra 注入，**不 import telethon** |

| api | `csx/api/routes/tg.py` | `GET /tg/client/status`、`POST /tg/client/scan` | application |

`domain/` 不改：频道/消息/游标没有领域规则需要落地，只是基础设施搬运。

## 2. 接口

### GET /api/v1/tg/client/status

```json
{
  "enabled": true,
  "configured": true,
  "running": true,
  "interval_minutes": 10,
  "last_scan_at": "2026-11-09T12:00:00Z",
  "last_error": null,
  "channels": [
    {"channel": "https://t.me/QukanMovie", "last_message_id": 12345, "scanned_at": "...", "ingested": 3, "error": null}
  ]
}
```

- `configured` = api_id + api_hash + session 三者齐备
- `running` = worker 线程任务存活

### POST /api/v1/tg/client/scan

同步触发一次全量扫描（阻塞到完成，最多 120s）：

```json
{"scanned_channels": 2, "new_messages": 37, "ingested": 4, "errors": ["..."]}
```

失败（未配置 / Telethon 登录失败）返回 422 + `{"code":"TG_NOT_CONFIGURED"|"TG_AUTH_FAILED", "message": "..."}`。

## 3. 数据落地

- 游标：`Setting.key = "tg.scan_state"`，value 为 JSON：
  ```json
  {"channels": {"https://t.me/QukanMovie": {"last_message_id": 12345, "scanned_at": "..."}},
   "last_scan_at": "...", "last_error": null}
  ```
  零迁移，不动 alembic。
- 消息 → 复用 `DiscoveredResource` / `TransferTask`（`ingest_telegram_message` 已有）。
- 配置来源：`advanced.tg_api_id / tg_api_hash / tg_session / tg_channels / tg_monitor_enabled / tg_interval_minutes`（设置页已存在）。

## 4. 失败与回滚

| 场景 | 处理 |
|---|---|
| 未配置 api_id/hash/session | worker 空转（每轮直接 return），状态 `configured=false`，不报错刷屏 |
| Telethon `AuthKeyUnregistered` / `UserDeactivated` | 记 `last_error`，worker 暂停本次启动（不重连），前端提示「会话失效，请重新导出 StringSession」 |
| `FloodWaitError` | 按 `seconds` 睡眠（上限 300s），本频道游标不前进，下轮重试 |
| 单频道 `ChannelPrivate` / `UsernameNotOccupied` | 该频道记 error，其余频道照常 |
| 进程重启 | 游标在库里，不会重复入库（ingest 本身按 dedup_key + 幂等键去重） |
| 想整体停 | 设置页关「Telegram 频道实时抓链监控」→ 下一轮 `configured/enabled=false` 直接退出循环 |

## 5. 并发与限流

- 单 worker 串行：整轮扫描串行处理频道，避免对 TG 侧并发请求触发风控。
- 每频道两次请求之间 `asyncio.sleep(1.5)`（10 个频道约 15s）。
- 全局：一轮扫描间隔默认 10 分钟（`tg_interval_minutes`，最小 1）。
- Telethon 会话单实例：worker 内持有 client，进程内只允许一个 client 对象。

## 7. 验收标准

1. `GET /tg/client/status` 返回真实配置状态，未配置时 `configured=false` 且不报错。
2. `POST /tg/client/scan` 用真实 session 扫描两个已配置频道，返回 `new_messages > 0`（或明确「无新消息」），不产生重复候选。
3. 连续触发两次 scan，第二次 `new_messages == 0`（游标生效）。
4. 关闭「频道实时抓链监控」并重启容器，worker 不再发起连接（日志无 Telethon 连接记录）。
5. `pytest` 全绿，新增单测 ≥ 6 条（未配置、认证失败、FloodWait、游标推进、单频道异常隔离、ingest 编排）。
6. `ruff check` / `ruff format --check` 零告警；`domain/` 无 telethon 引用。
7. 线上真机：设置页保存后 60s 内 `/tg/client/status` 显示 `running=true`。

## 8. 任务书（交给外部 runner）

处理「文本 → 解析 → 订阅匹配 → 建候选/任务」。现在要把 Telethon 客户端接进来定时拉频道。
