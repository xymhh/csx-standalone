> 需求来源：用户「补充媒体二级分类，去按 mp 的来，然后通知模板美化，同样留出通知模板配置」

## 1. 调研：MP 怎么做的（已取源码）

来源：`jxxghp/MoviePilot` v2 分支
- `app/modules/themoviedb/category.py`（`CategoryHelper.get_category`）
- `config/category.yaml`（默认策略）

### 1.1 数据形态

```yaml
movie:
  动画电影: {genre_ids: '16'}
  华语电影: {original_language: 'zh,cn,bo,za'}
  外语电影: {}            # 无条件 = 兜底
tv:
  国漫: {genre_ids: '16', origin_country: 'CN,TW,HK'}
  日番: {genre_ids: '16', origin_country: 'JP'}
  纪录片: {genre_ids: '99'}
  儿童: {genre_ids: '10762'}
  综艺: {genre_ids: '10764,10767'}
  国产剧: {origin_country: 'CN,TW,HK'}
  欧美剧: {origin_country: 'US,FR,GB,DE,ES,IT,NL,PT,RU,UK'}
  日韩剧: {origin_country: 'JP,KP,KR,TH,IN,SG'}
  未分类: {}
```

### 1.2 匹配规则（照抄语义）

1. 按配置顺序逐条匹配，**第一个命中的胜出**；空条件直接命中（兜底）。
2. 同一条规则内多个条件 **AND**。
3. 单个条件的值用 `,` 分隔，多值 **OR**。
4. `!值` 表示排除；`YYYY-YYYY` 表示年份区间。
5. 电影用 `production_countries`，剧集用 `origin_country`；年份取 `release_date` / `first_air_date` 前 4 位。
6. 值比较统一大写。

### 1.3 CSX 现状差距

| 项 | 现状 |
| --- | --- |
| 路径 | `电影/<片名 (年份)>/`、`剧集/<片名 (年份)>/Season 01/`，**无二级分类** |
| TMDB 详情 | `format_tmdb_item` 只返回 id/title/type/year/overview/海报/评分，**没有 genre_ids、语种、国家** |
| 配置 | 无 |
| 通知 | `*event*` + 逐行 `key: value`，无模板 |

## 2. 架构

### 2.1 二级分类

**存储**：`Setting` 表 section `category`，两个键：
- `category.movie`: `[{"name": "动画电影", "conditions": {"genre_ids": "16"}}, ...]`
- `category.tv`: 同上

用有序数组而不是 dict，保证前端可拖拽排序、JSON 稳定。

**算法**：`domain/category.py`（纯标准库，无外部依赖）

```python
def match_category(strategies: Sequence[Mapping], info: Mapping) -> str:
    """按顺序返回第一个命中的分类名；全不命中返回空串。"""
```

支持条件键：`genre_ids`、`original_language`、`production_countries`、`origin_country`、`release_year`，以及任意 TMDB 一级字段（与 MP 一致）。

**元数据来源**：`adapters/media/tmdb.py::get_detail` 扩展返回
`genre_ids`（由 `genres[].id` 得到）、`original_language`、`origin_country`、`production_countries`、`release_date`。
`organize` 时按 `media.tmdb_id` 拉一次（TMDB 客户端已有 30 分钟内存缓存）。

**路径**：`build_media_paths(..., category="动画电影")`
- 电影：`动画电影/<片名 (年份)>/<片名 (年份) [4K].mkv`
- 剧集：`国漫/<片名 (年份)>/Season 01/<片名 (年份) S01E01 [4K].mkv`
- `category` 为空时保持现状（向后兼容）。

**降级**：TMDB 拉不到详情 → 分类为空 → 不建二级目录，任务照常成功（不因分类失败阻塞转存）。

### 2.2 通知模板

**存储**：`Setting notify.templates`，形如：
```json
{
  "transfer_success": "🎬 *{{ title }}* ...",
  "upgrade_success": "...",
  "task_dead_letter": "..."
}
```

**渲染**：`domain/notify_template.py`
- `DEFAULT_TEMPLATES`: 三个事件的默认模板（Telegram MarkdownV2 安全，避免特殊字符）
- `render(template, payload) -> str`：Jinja2 `SandboxedEnvironment` + `ChainableUndefined`（复用 `application/naming.py` 的做法，但 domain 层不许依赖 jinja2 → **放 application 层**）

修正：`application/notify_template.py`。

**接入**：`NotificationDispatcher.dispatch` 拿到 `settings["templates"]`，按 event 渲染出 `text`，放进 payload 的 `_text` 键；各 sender 若 payload 含 `_text` 就直接发送该文本，否则回退旧的 key: value 格式（保证向后兼容与 webhook JSON 结构不变）。

**变量**：`title`、`season`、`episode`、`quality`、`from_quality`、`to_quality`、`duration`、`error`、`share_url`、`event`。

### 2.3 前端

- 设置页新增「媒体分类」卡片：
  - 顶部两个切换（电影 / 剧集）
  - 规则列表：分类名输入 + 条件行（字段下拉 + 值输入）+ 上移/下移/删除
  - 「添加规则」「恢复 MP 默认」
  - 说明文字：按顺序匹配，第一条命中即止；空条件为兜底
- 通知卡片新增「消息模板」折叠区：
  - 每个事件一个 textarea（等宽字体）+ 变量提示 chips + 「恢复默认」
  - 保存走现有 `PUT /settings/notify`

## 3. 失败与回滚

- 分类算法纯函数，无 IO，不会抛异常（输入脏数据时返回空串）。
- 路径变化只影响**新转存**，历史文件不迁移。
- 通知模板渲染失败 → 回退默认模板 → 再失败回退旧格式，绝不影响任务状态。

## 4. 验收

1. `match_category` 对 MP 默认策略的用例表全部命中（含 `!` 排除、年份区间、多值 OR、AND）。
2. 真实跑一条《奥德赛》：路径变为 `电影/外语电影/奥德赛 (2026)/...`。
3. 通知消息渲染出美化文本，改模板后生效。
4. 前端两个新区域可保存、可恢复默认、刷新后保持。
