# 功能对齐第 1 批任务书：网盘扫码登录（115 / 夸克）

> 状态：待开工
> 目标：对齐原 CS 插件的扫码登录成熟能力，彻底解决用户需要手动抓包复制 Cookie 的痛点。实现手机 App 一扫、点击确认即可自动将账号加密保存到系统中。

---

## 1. 架构与流程设计

### 1.1 业务流程
1. **用户操作**：在「设置」页点击「📱 扫码绑定网盘」，选择网盘类型（115 或 夸克），输入账号备注名（默认如「我的 115 账号」）。
2. **后端生成二维码**：
   - 115 驱动调用 `P115ClientManager.create_qrcode_login("alipaymini")`（或自适应渠道）生成二维码图片 Base64 与会话参数。
   - 夸克驱动调用 `QuarkClient.create_qrcode_login()` 生成二维码图片与 qr_token。
3. **前端轮询状态**：
   - 前端展示二维码图片，每 2 秒调用一次检测接口。
   - 状态流转：`waiting`（等待扫码）→ `scanned`（已扫码待确认）→ `success`（确认登录成功）/ `expired`（过期失效）。
4. **自动入库**：
   - 当状态检测为 `success` 并获取到网盘 Cookie 时，后端直接使用 Fernet 加密保存入 `account` 表。
   - 响应通知前端绑定成功，前端自动关闭弹窗并刷新账号列表。

### 1.2 接口规范

- `POST /api/v1/accounts/qrcode/start`：
  - 请求：`{"provider": "115" | "quark"}`
  - 响应：`{"provider": str, "qrcode": "data:image/png;base64,...", "token_data": dict, "hint": str}`
- `POST /api/v1/accounts/qrcode/check`：
  - 请求：`{"provider": "115" | "quark", "token_data": dict, "name": str, "auto_save": bool = true}`
  - 响应：
    - 等待中：`{"status": "waiting" | "scanned", "message": "请使用手机 App 扫码确认", "account": null}`
    - 成功：`{"status": "success", "message": "绑定成功", "account": {"id": int, "name": str, "provider": str}}`
    - 过期：`{"status": "expired", "message": "二维码已失效，请重新生成", "account": null}`

### 1.3 边界铁律
- `api/` 严禁直接 import `csx.vendor`，所有驱动调用必须通过 `csx/adapters/drive/`（`DriveRegistry.create_qrcode` / `check_qrcode`）封装。
- 最终产出的 Cookie 必须经 `csx/infra/credentials.py` 的 Fernet 工业级加密后入库，API 绝不向前端回传明文 Cookie。
