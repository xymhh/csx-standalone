# 订阅自动搜源（对齐 CS 插件订阅驱动）

> 状态：代码完成 2026-11-10，待真机验收 → ../test/2026-11-10-订阅自动搜源验收.md

## 目标

追剧订阅不再需要「自己搜 → 自己挑 → 自己转存」。开启后由后台定时为每部订阅搜全部已启用渠道，
命中缺失集且能转存的分享链接直接建 `transfer_task`，走既有 转存 → 整理 → STRM → 通知 链路。

## 架构

| 层 | 文件 | 职责 |
| --- | --- | --- |
| 搜源编排 | `backend/csx/application/auto_search.py` | 设置读写、单部搜源、整轮调度、判定与去重 |
| 进程内定时 | `backend/csx/infra/scheduler.py` | `csx-auto-search` 循环，每 300s 调一次回调 |
| 回调 | `backend/csx/infra/auto_search_runtime.py` | 读设置，`enabled=false` 直接返回 |
| API | `backend/csx/api/routes/auto_search.py` | `GET/PUT /api/v1/auto_search/settings`、`POST /api/v1/auto_search/run` |
| 单部触发 | `POST /api/v1/subscriptions/{id}/sync` | 改为真实搜源（原先只塞一条 pending 占位候选） |
| 前端 | `web/src/pages/SettingsPage.vue` | 「追剧与规则」页新增「订阅自动搜源」卡片 |

搜索层**不新写**：直接复用 `adapters/search/executor.search_resources`，渠道开关、顺序、熔断、15s 预算全部沿用。

## 判定规则（逐条过滤，命中即建）

1. 渠道类型必须是 `115` / `quark` 且 `can_transfer=true`（其它网盘、磁力不进自动转存）。
2. 标题归一化（去符号 + casefold）后包含媒体名，或 `SequenceMatcher ≥ 0.72`。
3. 标题中的年份若存在，与媒体年份差 ≤ 1。
4. 画质桶（`4k > 1080p > 720p > sd`）不低于订阅 `quality_pref.min_bucket`（默认 1080p）。
5. 剧集：`parse_episode_from_name` 解析出集数；须在订阅 `scope` 内，且该集尚未入库。
6. 去重：`dedup_key(provider, url)` 全局唯一；已存在直接跳过。
7. 幂等：`idempotency_key(provider, url, season, episode, bucket)` 决定 task 唯一性。

落库形态与 TG 频道自动转存完全一致：`discovered_resource(state=discovered/accepted)` +
`transfer_task`，因此 `transfer` 编排、失败重试、历史分组、通知都不需要改。

## 边界（明确不做）

- **整季包不自动转存**：标题解析不出单集（如「全12集」）时只落候选，`payload.whole_season=true`，
  由用户在「待选资源」点一次。原因：现有转存编排按单集匹配分享内文件，整包直转会误入库。
- 磁力 / 需积分解锁渠道不自动扣点、不自动解锁。
- 每部订阅单轮最多自动建 3 个任务，避免渠道异常时刷爆队列。
- 默认关闭；关闭时 `run_round` 直接返回 `skipped=auto_search_disabled`。

## 配置项（`Setting` 表 key=`auto_search`）

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| `enabled` | false | 总开关 |
| `interval_hours` | 6 | 同一部剧的搜源间隔（1–168） |
| `auto_transfer` | true | 关闭则只入候选 |
| `max_per_round` | 10 | 每轮最多处理多少部订阅（1–50） |
| `per_subscription_limit` | 20 | 每次向渠道要多少条（5–50） |

每部订阅的最后搜源时间存在 `Setting` key=`auto_search.last.<subscription_id>`，不新增表、不加迁移。

## 失败与回滚

- 单部订阅抛异常 → 回滚该部、记录日志、继续下一部。
- 整轮异常 → `auto_search_runtime` 吞掉并记日志，不影响任务轮询与签到循环。
- 回滚只需把 `enabled` 关掉；已建候选/任务按既有流程自然跑完。
