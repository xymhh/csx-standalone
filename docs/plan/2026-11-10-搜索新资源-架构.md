# 搜索新资源（接入后台已配置搜索渠道）— 架构

> 状态：待实现 2026-11-10
> 前置：`docs/plan/2026-11-10-传输与下载UI对齐CS插件.md`（已完成）

## 需求

「搜索」页不再是占位符，也不只是查 PanSou：
用户在设置里启用/配置过的搜索渠道（sources.*）全部参与搜索，结果聚合展示，可一键转存。
未配置的渠道不参与，但要能看到「未配置/未启用」状态，而不是静默消失。

## 轮子调研（结论：复用，不新写）

| 现成件 | 位置 | 覆盖 | 差距 |
| --- | --- | --- | --- |
| `SearchSourceRegistry` + 15 个渠道定义 | `backend/csx/vendor/search/*/definition.py` | 渠道元数据、配置表单、客户端/服务/Provider 组装 | 只用于设置页与连通性探测 |
| `create_search_registry(owner, config=...)` | `backend/csx/vendor/search/registry.py` | 按配置自动组装 `SearchRegistry`，跳过 push 型渠道 | 需要 owner 暴露 `_xxx` 配置属性 + `get_data/save_data` |
| `SearchProvider.search(SearchQuery)` | `backend/csx/vendor/core/search.py` | 统一入参/候选字段（title/url/resource_type/size/update_time…） | 需要 `MediaInfo` + `MediaType`，订阅上下文可为空 |
| `PanSouSearchService` 等 15 个 service | `backend/csx/vendor/search/*/service*.py` | 各渠道真实搜索与结果归一 | 构造函数各不相同，由 definition 内部处理 |

因此不自研搜索协议，只补一层「应用侧执行器 + 归一化」。

## 组件与职责

```
POST/GET /api/v1/search            → routes/search.py（参数校验、返回 envelope）
        ↓
adapters/search/executor.py        → 组装 owner shim + registry，并发搜索，归一化，逐源状态
        ↓
vendor/search/registry.py          → create_search_registry(owner, config)
        ↓
vendor/search/*/service.py         → 各渠道真实搜索
```

### owner shim

`SearchOwnerShim` 把扁平配置（`sources.<id>` 合并默认值）暴露成 vendor 期望的属性：

- `_pansou_url` ← `config["pansou_url"]`（`__getattr__` 统一加下划线映射）
- `_search_proxy` ← `config["search_proxy"]`；`None` 时不走代理
- `_resource_type_order_config` ← 全局 `resource_type_order` 设置，缺省 `115/quark/aliyun/uc/tianyi/123/magnet/ed2k`
- `get_data/save_data` ← 进程内 dict（积分账本缓存用，重启丢可接受）
- `_plugin`/`plugin` ← 自身（`storage_owner`）

### 搜索执行

- 输入：`q`、`type`（all/movie/tv）、`year`、`season`、`sources`（可选 id 列表）、`limit`（每源条数 10/20/30/50）
- 启用判定：`sources.<id>.enabled`，缺省 `True`；未在 registry 中注册 → 状态 `unconfigured`
- 并发：线程池，最多 4 个源同时跑，单源硬超时 25s
- `SearchQuery(mediainfo=MediaInfo(title=q, year=year), media_type=…, season=…, keyword=q, resource_list_mode=True, result_limit=limit)`
- 结果可能是 `list[dict]`（多数渠道）或 `dict[resource_type] -> list`（PanSou 列表模式），统一展平
- 归一化字段：`source / source_name / title / url / urls / password / resource_type / size / size_text / update_time / description / source_url / media_page_url / needs_unlock / can_transfer`
- 去重：同源同 URL 去重；跨源同 URL 保留首条并标注 `duplicate_of`
- 排序：标题命中（完全包含 > 部分）→ 更新时间倒序

### 转存边界

- `can_transfer = url` 是 `http(s)` 且 host 属于已支持的网盘（115/quark/aliyun/uc/tianyi/123/guangya/yun139 分享域名）
- 点击「转存」= 打开现有 `ManualTransferDialog` 并预填链接/提取码，用户确认目录后调用 `/drives/share/transfer`
- 磁力/ed2k：只给「复制链接」+（若已配置 115 账号）「115 离线」入口，不自动下载
- 需要积分解锁的渠道（dian115/hdhive/haven/pinglian 等）本轮只展示「需解锁」与积分数，不自动扣点

## 明确不做

- 不新增订阅搜索 worker（方案 B 留给下一轮）
- 不做跨源同名资源自动合并成「一个资源多个下载点」
- 不做结果持久化 / 收藏夹
- 不在前端做渠道级配置编辑（继续走设置页）

## 接口

`GET /api/v1/search/sources`
→ `{ sources: [{id,name,enabled,configured,order}] }`

`GET /api/v1/search?q=…&type=all&year=&season=&sources=a,b&limit=20`
→
```json
{
  "query": "…",
  "sources": [{"id":"mikan","name":"Mikan","status":"ok","count":29,"message":"","elapsed_ms":1830}],
  "items": [{ "id":"mikan:abc", "source":"mikan", "source_name":"Mikan", "title":"…",
              "url":"magnet:…", "resource_type":"magnet", "size":2022, "size_text":"2.0 KB",
              "update_time":"2023/04/16 14:27", "can_transfer":false, "needs_unlock":false }],
  "total": 29,
  "elapsed_ms": 2100
}
```

## 失败与回滚

- 单源异常只影响该源状态，HTTP 仍 200；全部源失败时 `items=[]` + 每源 message
- 前端「最近一次搜索」只在内存，刷新不恢复
- 无数据库变更，回滚只需回退镜像 tag
