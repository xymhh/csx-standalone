# 跨盘转存 —— 架构与实现规格

日期：2026-11-09
状态：进行中

## 1. 问题

订阅资源可能落在 A 盘（如夸克分享），而媒体库固定建在 B 盘（如 115）。当前 `application/transfer.py` 只用资源所在盘的适配器 `drives[provider]` 做同盘转存，因此：

- 资源是夸克分享、只配了 115 账号 → `drives["quark"]` 不存在，直接失败
- 即便两边都有账号，文件也只会进夸克，媒体库（115 上的 `/CSX/媒体库`）看不到

前端 `SettingsPage.vue` 已有「跨盘直传搬运」开关，但后端从未读取——是个假开关。

## 2. 目标与非目标

**目标**
1. 资源盘 ≠ 媒体库盘时自动中继：下载到本地缓存 → 目标盘秒传/上传 → 校验 → 清理
2. 库盘可配置（默认取 `is_primary` 账号，缺省 115）
3. 缓存目录可配置，默认 `/cache`，随容器挂载持久化
4. 失败语义与同盘一致：进 `retry_wait`，超次进 `dead_letter`，不静默成功

**非目标**
- 不做 115 离线下载直链方案（夸克直链带鉴权，115 离线大概率失败）
- 不做多源分片下载加速
- 不改 STRM / Emby 刷新链路

## 3. 数据流

```
资源(provider=quark, share_url) ──① 同盘转存──> 夸克 inbox/<key>/<file>
                                              │
                                    ② 取源盘真实文件（FILE_QUERY）
                                              │
                                    ③ 跨盘中继（下载→秒传/上传→校验）
                                              │
                                              ▼
                          目标盘(115) inbox/<key>/<file>  ──④ 整理──> 库目录
                                              │
                                    ⑤ 清理源盘中转文件 + 本地缓存
```

① 复用现有 `drive.transfer()`：源盘中转是秒级操作（115 分享转存走服务端），也为第②步提供可查询的真实文件对象（115 需要 pickcode，分享文件本身没有）。

## 4. 组件

### 4.1 `csx/infra/cross_transfer.py`（新）

```python
def build_vendor_providers(db) -> dict[str, CloudDriveProvider]
    # 115: create_p115_provider(P115ClientManager(cookie))
    # quark: create_quark_provider(QuarkDrive(QuarkClient(cookie=cookie)))
    # 账号来源：Account 表 is_enabled=True，按 is_primary desc, id asc 取第一个

class CrossTransferService:
    def __init__(self, db, cache_dir, threads, concurrent, direct_stream, rapid_miss_action)
    def manager(self) -> CrossTransferTaskManager
    def relay(self, source_key, source_file: CloudFile, target_key, target_dir,
              target_name) -> dict | None     # 阻塞等待，返回 {file_id, path, size, sha1, method}
    def cleanup_cache(self) -> int
```

- `CrossTransferTaskManager` 来自 `csx.vendor.core.transfer`，已具备：并发槽、断点续传、磁盘水位（<512MB 拒绝）、SHA1 缓存、秒传未命中负缓存、缓存引用计数
- 缓存目录 `cache_dir/<source_key>/`，任务完成后由 manager 自动删（`rapid_miss_action=abort` 时未命中也会删）
- provider 缓存按「账号凭据哈希」失效，避免换号后还用旧 cookie

### 4.2 设置（kv 表 `transfer.cross`）

```json
{
  "enabled": true,
  "library_drive": "115",
  "download_threads": 5,
  "max_concurrent": 2,
  "direct_stream": true,
  "cache_dir": "/cache"
}
```

- `library_drive` 为空时：取 `Account` 表里 `is_primary=True` 的第一个 provider，再不行取 `115`
- `cache_dir` 必须是可写目录，启动时 `mkdir -p`；不可写则回退 `/tmp/csx-cache` 并告警


若 `target_provider != provider` 且目标盘未配置账号 → 任务直接 `dead_letter`，错误信息明确写「媒体库盘 115 未配置账号」。

## 5. 失败与回滚

| 场景 | 行为 |
| --- | --- |
| 目标盘无账号 | 任务 `dead_letter`，错误「媒体库盘 X 未配置账号」 |
| 缓存目录不可写 / 空间 <512MB | 任务 `retry_wait`，错误「本地缓存空间不足」 |
| 下载中断 | manager 支持断点续传；任务 `retry_wait` 下轮续传 |
| 秒传未命中 | 按 `rapid_miss_action`：`abort` 换下一个分享重试 / `fallback` 普通上传 |
| 上传成功但查不到文件 | 任务 `retry_wait`，错误「上传后未在目标盘找到文件」 |
| 源盘中转删除失败 | 仅记日志，不影响任务成功 |

回滚：设置里把 `enabled` 关掉即回到同盘逻辑；代码层面无 schema 迁移，`transfer.cross` 是纯 kv。

## 6. 测试要点

1. `resolve_library_drive`：设置优先、is_primary 次之、缺省 115
2. 跨盘判定：同盘不走 relay，异盘走
3. relay 成功 → `outcome.created` 用目标盘 file_id/path
4. relay 失败 → 任务进 retry_wait，错误信息含文件名
5. 目标盘未配置 → dead_letter
6. 缓存目录不可写 → 回退 /tmp 且不崩
7. `upsert_episode_file` 记录的是目标盘 provider
