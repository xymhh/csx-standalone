# 传输与下载（正在转存 / 转存历史）UI 对齐 CS 插件

> 状态：已实施 2026-11-10 → ../summary/2026-11-10-传输与下载UI对齐CS插件-完成.md

## 1. 用户诉求

原话：「csx 正在转存和转存历史 UI 按照 cs 插件来」。

当前 CSX「传输与下载」两个页签是**开发者视角**的裸表：

- 正在转存：`任务 #4` + 一串 `idempotency_key` 哈希 + 状态 + 尝试次数，看不到片名、集数、网盘、大小。
- 转存历史：表格列 `任务编号 / 状态 / 尝试次数 / 错误信息 / 时间`，全部是任务 ID，无法回答「哪部剧、哪一集、为什么失败」。

CS 插件的对应界面是**业务视角**：按媒体汇总 + 展开集明细 + 彩色状态 + 失败原因短标签 + 多条件筛选 + 批量重试。

## 2. 现状差距（含真实 bug）

| 项                 | CSX 现状                                             | CS 插件                                         |
| ------------------ | ---------------------------------------------------- | ----------------------------------------------- |
| 行的主体           | 任务 ID                                              | 媒体（片名 + 年份 + 海报）                      |
| 失败信息           | 原始 `last_error` 全文，最长一行截断                 | 短标签「未命中秒传 ×2」，悬停看全量             |
| 汇总               | 无                                                   | 成功 N / 待完成 N / 失败 N / 跳过 N / 待确认 N  |
| 展开明细           | 无                                                   | 每集一行：文件名/大小/来源/状态/失败原因/时间   |
| 筛选               | 只有一个 `provider` 输入框                           | 状态/来源/任务类型/资源类型 多选 + 关键词搜索   |
| 批量操作           | 仅 `dead_letter` 可勾选重试                          | 重试全部失败 / 重试选中 / 删除所选              |
| 分页               | 后端有 page 参数但前端不展示、拿不到 total           | 服务端分页 + 每页条数                           |
| 移动端             | 表格横向挤压                                         | 卡片列表                                        |

**顺带修的真 bug**：`GET /api/v1/tasks` 不传 state 时返回**全部状态**，所以「正在转存」页签里混着「已完成」的历史任务；前端 `tasksApi.list()` 正是无参调用。

## 3. 目标信息架构

### 3.1 正在转存（进行中）

按媒体分组，每部一张卡：

```
[海报 2:3]  谷雨 (2026)          [转存中]        [取消]
            剧集 · 第 12 集 · 夸克 · 4K
            阶段：整理归档  |  第 1 次尝试  |  已用 2 分 14 秒
            失败行（若有）：未命中秒传 · 悬停看详情   [立即重试]
```

- 状态胶囊：排队中 / 转存中 / 等待重试（60s 后）/ 转存失败。
- 无真实进度百分比就不显示百分比（拒绝假可用）；用**阶段文案**替代：校验分享 → 转存中 → 整理归档 → 生成 STRM → 通知。
- 顶部一行小结：`转存中 2 · 排队 1 · 等待重试 1`。
- 空态保留现有文案。

### 3.2 转存历史

沿用 CS 插件的分组表，换成 CSX 暗色设计语言：

```
[筛选] [搜索片名/文件名]             [重试全部失败(3)] [刷新]
────────────────────────────────────────────────────────────
▸ [海报] 谷雨 (2026)   夸克   剧集 · 3 条 · 6.6 GB
         成功 2 / 失败 1 / 跳过 0 · 未命中秒传 ×1        09:12
▾ 奥德赛 (2026)        115    电影 · 1 条 · 82 GB
   ┌ 集号  文件名                                大小    来源  状态    失败原因   时间
   │ E01   奥德赛 (2026).mkv                     82 GB   115   已入库  —         09:41
   └ ...
```

- 行内：海报缩略图、片名(年份)、网盘徽标、类型 · 记录数 · 总大小、成功/失败/跳过计数、失败原因短标签（最多 2 类）、最新时间。
- 展开：每集明细（集号、文件名、大小、来源、画质、状态、失败原因、时间、重试按钮）。
- 筛选：状态（已入库/失败/跳过）、来源（115/夸克/TG 频道/手动）、关键词。
- 批量：勾选失败项重试、重试全部失败；**不做删除**（CSX 没有删除关联文件的实现，避免留僵尸按钮）。
- 服务端分页：`共 N 条 / 第 x-y 条`，每页 20/50/100。
- 移动端：卡片列表，点开展开明细。

## 4. 数据缺口与后端改动

现有可 join 到的字段（已验证线上真实数据）：

- `transfer_task` → `subscription` → `media_item`：title / year / type / poster_url / tmdb_id
- `transfer_task` → `discovered_resource`：provider、`payload`（title 原始发布名、season、episode、quality_bucket、source=telegram/manual）
- `manual_transfer` → `account`：无订阅的 TG/手动任务的 provider
- `library_file`（media_id + season + episode）：落地路径、真实大小、画质

需新增：

1. **`GET /api/v1/tasks` 只返回进行中状态**（queued/running/retry_wait/dead_letter），并补 enrich 字段：`media_title/media_year/media_type/poster_url/season/episode/provider/quality_bucket/display_name`。
2. **`transfer_task.stage` 列 + 迁移 `0010_task_stage`**，在 transfer 流程 4 个节点写入（`checking` / `transferring` / `organizing` / `postprocess`），失败时清空。仅用于展示阶段，不做百分比。
3. **`GET /api/v1/history` 改为分组返回**：
   ```json
   { "groups": [ { "key": "media:4", "title": "谷雨", "year": 2026, "type": "tv",
                   "poster_url": "...", "providers": ["quark"], "total_size": 6600000000,
                   "counts": {"succeeded":2,"failed":1,"skipped":0},
                   "failure_labels": [{"label":"未命中秒传","count":1}],
                   "latest_at": "...", "records": [ ... ] } ],
     "total": 12, "page": 1, "page_size": 20,
     "filter_options": { "providers": ["quark","115"], "states": ["succeeded","failed","skipped"] } }
   ```
4. **失败原因归一化**：`application/failure_label.py`，把 `last_error` 映射为短标签（未命中秒传 / 分享失效 / 提取码错误 / 目标目录无权限 / 整理失败 / 网络超时 / 其他），保留原文供悬停。
5. `POST /api/v1/history/retry_batch` 复用现有实现，前端传勾选 ID。

**不做**（明确排除，避免扩张）：删除历史记录 / 删除网盘文件、洗版、补发通知、待确认状态、资源链接数、Emby 播放按钮。

## 5. 验收标准

- 线上 `https://csx.xymhh.eu.org/tasks`：正在转存不再出现「已完成」；每条都能看到片名、集数、网盘、阶段。
- 转存历史按媒体分组，能展开看到每集文件名/大小/失败原因；筛选与分页可用；「重试全部失败」真的把失败项重新排队（`/api/v1/tasks` 出现 queued 记录）。
- 移动端 390px 宽不横向溢出。
- `pytest` 全绿 + `ruff check`/`ruff format --check` + `vue-tsc` + `vite build` 通过，镜像 `sha-<commit>` 部署并真机截图核验。

## 6. 工作量

后端 2–3 小时（enrich + 分组 + stage 迁移 + 单测），前端 3–4 小时（两页 + 移动端 + 筛选分页），真机验收 30 分钟。
