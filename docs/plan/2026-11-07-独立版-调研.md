## 三、结论：拼装

### 为什么不自研全套
没有单个项目覆盖「订阅基线 → 缺集计算 → 双源发现 → 转存 → 秒传 → 整理 → STRM → 媒体库回写」这条完整链。唯一覆盖的是 MoviePilot 本体，而它正是要脱离的对象。

### 为什么不改造现成项目
- CloudSaver（MIT）：搜索+转存是同类，但没有订阅基线、没有整理、没有 STRM。改造它等于重写 70%。
- TgtoDrive（MIT）：只有 TG 一条源，本项目的价值在于「订阅 + 双源」，接上等于架空它。
- Alist/OpenList（AGPL）：是文件层，不是业务层，且 AGPL 比 GPL 更严。

### 具体拼装方案

| 层 | 来源 |
|---|---|
| 网盘驱动（7 家） | **继承现有** `drive/` 15,165 行（GPLv3 一致） |
| 搜索源（14 个） | **继承现有** `search/` 24,617 行 |
| 数据层 | **继承现有** `core/database/` 3,213 行（SQLAlchemy + SQLite） |
| Web 框架 | FastAPI + uvicorn（现成） |
| 调度 | APScheduler（现成，现有代码已在用） |
| 前端 | Vue 3 + Vite + Tailwind 4 + shadcn-vue + Reka UI（现成） |
| 前端 IA | **照 `csx-console/` 的 10 页设计** |
| 业务核心 | **自研**（订阅状态机 / 整理链 / 片名识别 / 任务编排） |

## 四、许可证核对

- 现有仓库 `LICENSE` = **GPLv3**，用户确认新项目同为 **GPLv3** → 继承 43,000 行合规。
- MoviePilot 也是 GPL-3.0 → 调用其 HTTP API 可以，复制源码进新项目虽同许可但没必要，**按「只调用不复制」执行**。
- Alist / OpenList / quark-auto-save / cloud-auto-save-x 是 **AGPL-3.0**，比 GPL 更严格（网络服务也要开源）。本项目**不复制其代码**，避免 AGPL 传染。
