## 1. 详细规格与文件落点

### 1.1 在线热备与恢复核心 `csx/infra/backup.py`
- **在线热备**：
  - 使用 SQLite 的 `VACUUM INTO '<temp_path>'` 命令实现非阻塞、强一致性的在线快照备份，服务在备份期间继续读写不受影响
  - 产物支持 gzip 压缩，命名格式：`csx-backup-YYYYMMDD-HHMMSS.db.gz`
  - 备份目录默认保存在 `<data_dir>/backups/`
  - 计算并记录备份文件的 SHA256 校验和、大小、生成时间与包含的表统计
- **安全恢复**：
  - 先解压并检验 SQLite 头部魔数（`SQLite format 3\0`）与完整性（`PRAGMA integrity_check`）
  - 恢复前自动对现有活跃数据库建一份紧急快照 `<db>.pre-restore.bak`
  - 采用原子重命名替换当前数据库文件
- **API 暴露（`csx/api/routes/system.py`）**：
  - `POST /api/v1/system/backup`：触发一次在线热备，返回备份产物信息
  - `GET /api/v1/system/backups`：列出已有备份文件清单（按时间倒序）

### 1.2 CLI 工具入口
- `python -m csx.tools.backup`：命令行直接触发备份
- `python -m csx.tools.restore <backup_file_path>`：命令行安全恢复指定备份

### 1.3 崩溃自愈机制 `csx/infra/bootstrap.py`
- **孤儿任务自愈 `recover_stale_tasks()`**：
  - 当容器或进程意外断电/崩溃重启时，上次处于 `running` 状态的任务会永久卡死
  - 在应用启动流程（`init_db()` 之后）自动扫描 `state == 'running'` 的任务
  - 处理规则：
    - 若 `attempt < 3`：将其状态重置为 `retry_wait`，`next_retry_at` 设为当前时间，由调度器重新拉取重试
    - 若 `attempt >= 3`：标记为 `dead_letter`，记录错误 `PROCESS_CRASHED_ORPHAN`
  - 记录警告日志并广播一条系统恢复事件

### 1.4 数据库迁移可逆性与健康检查

- 确保所有的 `CREATE TABLE` 与 `CREATE INDEX` 均使用 `IF NOT EXISTS`，任何中间版本的重复执行均幂等安全
