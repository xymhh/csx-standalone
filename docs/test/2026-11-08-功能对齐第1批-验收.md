# 功能对齐第 1 批：网盘扫码登录验收

## 实现内容

- `backend/csx/adapters/drive/registry.py` 增加 `DriveRegistry.create_qrcode` 与 `check_qrcode`：115 调用 `P115ClientManager` 的扫码登录接口；夸克调用 `QuarkClient` 接口，并在 adapter 内将 vendor 提供的二维码 URL 渲染为 PNG data URI。状态统一为 waiting/scanned/success/expired，Cookie 只在 adapter 与 API 之间传递。
- `backend/csx/api/routes/resources.py` 增加鉴权路由 `POST /api/v1/accounts/qrcode/start` 与 `POST /api/v1/accounts/qrcode/check`。成功且开启 `auto_save` 时使用现有 Fernet 凭据加密器保存账号并返回脱敏账号对象；响应不包含 Cookie。保留账号表 provider 唯一约束，已有同类账号时返回 `ACCOUNT_EXISTS`，不覆盖现有凭据。
- `web/src/lib/api.ts` 增加强类型 `accountsApi.startQrcode` / `checkQrcode`。
- Settings 的「我的网盘账号」增加扫码绑定按钮和扫码 Dialog，支持选 115/夸克、备注名、显示二维码、每 2 秒轮询状态、过期重建、成功后自动关闭并刷新列表。关闭弹窗或离开页面会清理定时器；轮询请求带会话序号，避免旧请求覆盖新二维码状态。手动绑定仍保留。
- 新增 `backend/tests/test_api_qrcode.py`：覆盖两家二维码图片与 token 字段、waiting/scanned/expired、自动加密入库、禁止 Cookie 回显、关闭自动保存、已有账号冲突和接口鉴权。自动化测试全部 Mock vendor，不联网。

## 真实二维码生成调用

使用隔离临时 SQLite 和临时管理员登录，通过 TestClient 实际调用两家已鉴权 HTTP API，验证 data URI、Base64 解码和 PNG 文件头。没有输出或保存二维码 token 内容。

```text
authenticated API QR checks: [('115', 951, ['client_type', 'sign', 'time', 'uid']), ('quark', 1888, ['qr_token'])]
```

这项检查只生成登录二维码并验证其图片格式，没有扫码确认登录或创建真实账号。
