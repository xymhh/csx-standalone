## 1. 做了什么

用户要求「要域名，先加上管理员账户」。先补鉴权，再开公网，顺序不能反——没有鉴权的 P0 页面直接暴露公网等于裸奔。

### 后端

| 文件 | 作用 |
| --- | --- |
| `backend/csx/infra/security.py` | `scrypt`(n=2^14,r=8,p=1) 口令哈希、`secrets.token_urlsafe(32)` 会话令牌、`sha256` 指纹 |
| `backend/csx/infra/db.py` | SQLite engine（`data/csx.db`）+ `SessionLocal` |
| `backend/csx/infra/models.py` | `admin_user`、`auth_session` 两表 |
| `backend/csx/infra/bootstrap.py` | 启动时建表；无管理员则按 `CSX_ADMIN_USER/PASSWORD` 创建，未给口令则随机生成写入 `data/initial-admin-password.txt`(0600) |
| `backend/csx/infra/ratelimit.py` | 进程内登录失败限流（默认 5 次 / 900s，按 IP） |
| `backend/csx/application/auth.py` | 登录校验、建/查/删会话、改密（改密后清空该用户全部会话） |
| `backend/csx/api/deps.py` | `current_user` 依赖 + cookie 名 `csx_session` |
| `backend/csx/api/routes/auth.py` | `POST /auth/login`、`POST /auth/logout`、`GET /auth/me`、`POST /auth/password` |
| `backend/csx/api/main.py` | `auth_guard` 中间件（白名单只有 `/health`、`/api/v1/auth/login`）、`HTTPException` 统一包络、`SPAStaticFiles` 前端 history 回退 |

### 前端

- `web/src/router.ts`：`/login` 公开，其余路由进守卫（`authApi.me()` 失败即跳登录并带 `next`）。
- `web/src/pages/LoginPage.vue`：shadcn 风格卡片登录页。
- `web/src/pages/HomePage.vue`：原骨架页，加「登录为 xxx」与退出。
- `web/src/lib/api.ts`：401 时派发 `csx:unauthorized` 事件，由 router 统一跳转，调用点不用各写一遍。

## 5. 这次踩到的 1Panel 坑（新增，之前记的仍然有效）

1. **`files/decompress` 又一次假成功**：返回 `{"code":200,"message":"success"}` 但目录 `modTime` 没变。判断是否真解压不能看返回值，要看目标目录 `modTime`（`files/content` 可读）。
2. **`containers/compose` 创建接口**：`template` 必须是数字（`"0"` 报 `cannot unmarshal string`）；`from` 必填且只接受 `template`/`edit`（`blank`/`appstore`/`local`/`compose` 全部 oneof 校验失败）；用 `from:"edit"` + `file` 建出来的记录 `composeFile` 仍为空。
3. **`compose/operate` 的 `path` 要指到文件**：传目录会报 `compose file "…" is invalid: … is a directory`。传 `.../docker-compose.yml` 才对。
4. **`files/save` 的 `content` 用 base64 会写坏 YAML**（出现 `top-level object must be a mapping`）；直接传明文 `content` 正常。
5. **改了镜像内容必须换 tag**：`compose up` 命中已有 `image:` 不会重建。这次用 `csx-standalone:p05 → p08` 逐次递增强制重建，旧 tag 用 `POST /containers/image/remove {"names":["csx-standalone:p05"]}` 清掉。
6. **容器名冲突**：`compose down` 因项目名不一致不生效，会报 `orphan containers` + `container name already in use`；改用 `POST /containers/operate {"names":[...],"operation":"remove"}` 直接删容器再 up。
7. **`files/del` 的字段是 `path` + `files`**（不是 `paths`），目录要 `recursive:true`。
