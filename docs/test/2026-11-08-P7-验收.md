# P7 稳定化验收记录

## 交付内容

- `backend/csx/infra/backup.py`：调用 SQLAlchemy `engine.raw_connection()` 执行 SQLite `VACUUM INTO`，生成 `csx-backup-YYYYMMDD-HHMMSS.db.gz`；流式计算 SHA256，保存压缩文件、大小、生成时间与表行数 manifest。恢复时先验证 manifest 校验和（存在时）、gzip 解压、SQLite 文件头与 `PRAGMA integrity_check`，然后生成 `<db>.pre-restore.bak` 紧急快照并原子替换活动数据库。
- `backend/csx/tools/backup.py`、`backend/csx/tools/restore.py`：支持 `python -m csx.tools.backup` 和 `python -m csx.tools.restore <backup_file_path>`。
- `backend/csx/infra/bootstrap.py`：迁移后扫描 `running` 孤儿任务；attempt `< 3` 改为 `retry_wait` 并立即可重试，attempt `>= 3` 标记 `dead_letter`；记录 `PROCESS_CRASHED_ORPHAN`，记录 warning 并广播 `system_recovery` SSE 事件。
- `backend/csx/api/routes/system.py`：鉴权保护的 `POST /api/v1/system/backup` 与 `GET /api/v1/system/backups`，统一使用 `ok` 包络；已挂载至主路由。
- `backend/tests/test_backup_restore.py`：并发写入时热备、压缩和 checksum、恢复后的内容和紧急快照、损坏文件拒绝及活动库不变。
- `backend/tests/test_crash_recovery.py`：attempt 未超限、达到上限、非 running 任务隔离和重复自愈。
- `backend/tests/test_migrations_reversibility.py`：对临时 SQLite 执行 head 重复升级、降至 0001、再次升级的两轮闭环，核对表、列和索引。
- `backend/tests/test_api_system.py`：备份端点未登录 401、已登录创建和列出备份的包络。
- 根目录 `README.md`：更新 P0–P7 完成状态、部署步骤、完整环境变量表、日常运维命令、备份恢复步骤、故障排查表及阶段文档链接。

恢复 CLI 需要在服务停止时运行，以避免其他进程持有数据库连接；系统 API 目前提供在线备份和备份清单，不提供在线恢复。
