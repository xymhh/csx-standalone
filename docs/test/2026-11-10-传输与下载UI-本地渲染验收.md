## 2. 本地真实渲染（真实浏览器 + 真实数据，非 mock）

环境：本机 uvicorn（临时数据目录）+ `scripts/seed_ui_preview.py` 造 9 条任务 / 3 部影视，
Chromium 实际登录后截图，视口 **1280×900** 与 **390×844 @2x**。

### 正在转存

- 按媒体分组卡片：海报、片名+年份、`电影/剧集`、状态汇总（转存中 2 · 等待重试 2 · 失败 1）。
- 每行：集号 chip、发布名、网盘、阶段徽章、画质；running 行有 3 段阶段轨道（校验分享→转存中→整理入库），**无百分比**。
- retry_wait 行显示「等待重试」+ 下次重试时间 + 立即重试；queued 行有取消；dead_letter 行显示失败短标签（`未命中秒传`、`未配置网盘账号`、`整理归档失败`），悬停看原始错误。
- 电影行不显示无意义的 `S01E01`。
- 移动端：标题占独立两行不截断，徽章换行，操作按钮仍可点。

### 转存历史

- 顶部：状态胶囊（全部/已入库/失败/跳过）+ 关键词搜索（300ms 防抖）+ 来源下拉（来自真实 `filter_options`）+ 刷新 + 重试全部失败(N)。
- 分组行：海报、片名+年份、来源徽章、成功/失败/跳过计数、失败原因前 2 类（`×数量`）、最近时间、悬停「重试失败」。
- 展开后逐集明细：`S01E12`、发布名、大小、来源、画质、状态、失败短标签（悬停原始错误）、相对时间、单条重试。
- 桌面一行看全；移动端文件名独立占行、元信息折行、状态与重试右对齐。
- 分页：`共 N 部 · M 条记录`、每页 20/50/100、上一页/页码/下一页。

## 3. 已知未覆盖

- 「生成 STRM」阶段没有单独写入 stage：STRM 在任务成功后由 side_effects 异步执行，任务已离开 `running`，故阶段轨道止于「整理入库」。蓝图里第 4 步据此不展示。
- 历史分组在内存里聚合（当前量级 < 千条）；数据量再上一个量级时应改为 SQL 聚合 + 分组分页。
